## 2. 논문 코드가 문서와 달랐던 점 5가지

`process_subject`를 정독해 확인했다. **순서가 결과를 바꾸므로 그대로 따라야 한다.**

### ① Y축 반전이 맨 앞에 있다 — 가장 중요

```python
res[:,1::3] = 50 + res[:,1::3].max() - res[:,1::3]
```

영상 좌표는 y가 아래로 증가한다. 반전하지 않으면 코 높이의 극대·극소가 뒤바뀌어 **기립과 착석이 반대로 잡힌다.** 초기 구현에서 이걸 빠뜨려 시간 오차가 MAE 2.39초까지 벌어졌다.

### ② 정규화가 2단계다

문서에는 "신장 정규화 — 코–발목 거리의 95백분위수"만 적혀 있었으나 실제로는 둘이다.

| 단계 | 원점 | 스케일 | 용도 |
|---|---|---|---|
| 1차 `center_ts` | 우측 발목(5~95백분위 평균) | **목–중앙고관절 거리** | 국면 분할용 |
| 2차 | 매 프레임 우측 발목 | **코–발목 95백분위수** | 지표 산출용 |

### ③ 국면 분할 신호는 코 단독이 아니다

`(코_y + 목_y) / 2` 를 쓴다. 스플라인 평활 후 peakdet 로 극값을 찾고, 구간별 국소 극소로 착석 시점을 다시 보정한다.

### ④ 평활은 국면 분할 **이후**에 적용된다

문서의 순서(전처리 → 국면 분할)와 반대다. 실제로는 `center_ts` → **국면 분할** → 신장 추정 → 6Hz 평활 → 2차 정규화 순이다.

### ⑤ 필터가 zero-lag 가 아니다

```python
def butter_lowpass_filter(data, cutoff, fs, order=5):
    y = lfilter(b, a, data)      # 단방향. filtfilt 가 아니다
```

**논문 본문의 "fifth-order zero-lag" 기술과 공개 코드가 불일치한다.** 계획서 §3.4가 "Phase 1에서 논문 코드와 대조하여 확정한다"고 남겨둔 항목의 답이다.

`lfilter`는 위상 지연을 남기고, **시간을 재는 연구에서 위상 지연은 그대로 편향**이 된다. `sts_metrics.py`는 `zero_lag` 인자로 둘 다 지원하며 기본값은 논문 재현(lfilter)이다. **자체 데이터 분석에는 `--zero-lag`(filtfilt)를 쓸 것.**

### 부수 — `max`/`min` 은 실제 최대·최소가 아니다

각 반복 구간의 **95 / 5 백분위수**다. 이상치에 강건하게 만든 선택이며, 우리 지표를 논문과 비교할 때 같은 정의를 써야 한다.

## 3. 논문 공개 코드의 버그 2건

재현을 위해 `paper_compat=True`(기본값)에서 그대로 재현하고, `False`로 두면 바로잡은 값을 낸다.

### 버그 ① `_ang_acc` 가 각가속도가 아니라 각속도다

`utils.py:394`

```python
"{}_ang_vel{}".format(name,sts): np.array(vel).mean(),
"{}_ang_acc{}".format(name,sts): np.array(vel).mean(),   # <- acc 가 아니라 vel
```

가속도 `acc` 를 계산해 놓고 반환하지 않는다. **공개 데이터에서 실측 확인했다** — `dataClean.csv`·`dataMovement.csv`의 아래 11개 열이 대응하는 `_ang_vel` 열과 **완전히 동일한 값**이다.

```
left_knee_ang_acc        right_knee_ang_acc
left_hip_ang_acc         right_hip_ang_acc
left_ankle_ang_acc       right_ankle_ang_acc
trunk_lean_ang_acc
left_shank_angle_ang_acc right_shank_angle_ang_acc
alignment_ang_acc        trunk_ang_acc
```

### 버그 ② `_range_mean` 이 마지막 주기를 중복 집계한다

`utils.py:363-375`의 둘째 루프가 `lang`만 갱신하고 `y`는 갱신하지 않아, 마지막 주기의 범위가 주기 수만큼 추가로 들어간다. 결과적으로 `range_mean`은 `(전체 주기 평균 + 마지막 주기 값) / 2` 에 가까워진다.

## 4. Phase 4 에 미치는 영향 — 조치 필요

**`trunk_lean_ang_acc` 는 `phase4_incremental.py:72` 의 `QUALITY_KINEMATIC` 특징 목록에 들어 있다.** 그런데 그 열은 각가속도가 아니라 각속도다.

```
docs/20260805_Phase4_증분가치분석_결과.md §6
  trunk_lean_ang_acc   R = -0.103   p = 0.039   [운동학]
```

이 값은 **체간 각속도와 골관절염의 연관**으로 읽어야 한다.

### 결과에 미치는 영향

- **수치는 바뀌지 않는다.** 같은 열을 그대로 썼으므로 ΔR²·ΔAUC 등 Phase 4 결론 3가지는 그대로 유효하다
- **해석과 표기가 바뀐다.** 최종 보고서에서 이 특징을 `각가속도`로 부르면 틀린 기술이 된다
- **계획서 §3.7 사전등록 기대치표의 `각가속도` 행**은 "Boswell 2023 r=0.556"을 근거로 ICC 0.40–0.70을 예상하는데, 그 근거값이 실제로 무엇을 가리키는지 재확인이 필요하다
- **선행 논문이 보고한 "체간 각가속도" 관련 서술도 같은 열에 근거한다.** 공개된 산출물 기준으로는 각속도다

### 조치

1. `phase4_incremental.py` 에 주석으로 명시 — **완료**
2. 최종 보고서에서 이 특징을 `체간 각속도`로 표기
3. Phase 3에서 각가속도의 신뢰도를 평가할 때는 **직접 계산한 값**을 쓸 것(`paper_compat=False`)
4. 이 발견 자체를 방법론 기여로 기술할 수 있다 — 국면 시간 중복(r=0.972) 발견과 같은 성격이다

## 5. MediaPipe 계층

### 설치

```bash
pip install mediapipe          # 1.0.0 확인. Python 3.13 에서 동작
python scripts/mediapipe_pose.py --download-model   # 모델 별도 (약 9MB)
```

**MediaPipe 1.0 은 구 `mp.solutions` API 를 제거했다.** Tasks API(`PoseLandmarker`)만 남았고 `.task` 모델 파일을 별도로 받아야 한다. 인터넷 검색 결과나 구버전 예제 코드는 대부분 `mp.solutions.pose` 를 쓰므로 그대로는 동작하지 않는다.

### landmark 매핑 — MediaPipe 33 → OpenPose BODY_25

핵심은 **MediaPipe 에 없는 관절 2개를 만들어야 한다**는 점이다.

| BODY_25 | MediaPipe | 비고 |
|---|---|---|
| `NECK`(1) | 좌우 어깨의 **중점** | MediaPipe 에 목이 없다 |
| `MHIP`(8) | 좌우 고관절의 **중점** | **골반 정의 차이의 핵심** |
| `LSTO`/`RSTO` | `foot_index` 로 근사 | 소지 구분이 없다 |

나머지는 1:1 대응한다. 좌/우 표기는 두 모델 모두 **피험자 기준**이라 뒤집을 필요가 없다.

이것이 계획서 §7-6 한계 "MediaPipe(33)와 OpenPose(25)는 골반 정의가 달라 직접 비교 불가"의 구체적 내용이다. 논문 수치와 직접 비교하지 않고, **전처리를 동일하게 맞춰 방법 수준의 비교만** 한다.

### 사용

```bash
python scripts/mediapipe_pose.py video.mp4 --zero-lag \
       --height 175 --weight 70 --chair 45
```

출력: 5STS 총 시간, 국면별 시간, AWGS 임계값 판정, Alcazar 상대파워, 체간 경사·무릎·고관절 각도, 좌우 비대칭.

### 아직 검증되지 않은 것

- **실제 영상으로 돌려본 적이 없다.** 자세추정 정확도, 국면 분할 성공률 미지
- MediaPipe 궤적에서 `center_ts`·국면 분할이 OpenPose 만큼 안정적인지 미확인
- 신뢰도(confidence) 임계 0.5 가 MediaPipe `visibility` 에 적절한지 미검토

**다음 작업**: 본인 스마트폰으로 5STS 를 촬영해 end-to-end 확인. Kinect 불필요.

## 7. 최종 보고서용 문구

> 선행 연구의 특징 추출 파이프라인을 독립적으로 재구현하여 공개 궤적에 적용하였다. 저자가 피험자별 수동 보정을 적용하지 않은 217명에서 시간·각도·속도 계열 13개 지표가 상관계수 1.0000, 평균절대오차 0.0000으로 완전히 일치하였다. 수동 보정이 적용된 피험자에서만 불일치가 관찰되어, 차이의 원인이 구현이 아니라 미적용한 피험자별 개입임을 확인하였다.
>
> 재구현 과정에서 공개 코드와 논문 기술 간 불일치 및 산출 오류를 확인하였다. 첫째, 논문은 5차 zero-lag 필터를 기술하였으나 공개 코드는 단방향 `lfilter`를 사용하여 위상 지연이 보정되지 않는다. 둘째, 각가속도로 명명된 산출값이 실제로는 각속도의 평균을 반환하며, 공개 데이터의 해당 11개 열이 각속도 열과 동일한 값임을 확인하였다. 본 연구는 재현성을 위해 원 구현을 그대로 재현하는 모드와 이를 보정한 모드를 함께 제공한다.
