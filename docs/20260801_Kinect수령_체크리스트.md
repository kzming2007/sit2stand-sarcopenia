## A. 연구실에서 반드시 챙길 것

| | 품목 | 없으면 |
|---|---|---|
| ☐ | **Azure Kinect DK 본체** | — |
| ☐ | **전원 어댑터 (필수)** | USB-C 단독 전원은 불안정. 깊이 카메라가 안 켜지거나 끊긴다 |
| ☐ | **USB-C 3.0 데이터 케이블** | USB 2.0 케이블은 대역폭 부족으로 실패 |
| ☐ | 삼각대 또는 마운트 | 본체 하단에 1/4-20 표준 나사. 일반 카메라 삼각대 호환 |
| ☐ | 운반 가방·케이스 | 광학 장비다. 충격 주의 |

> **전원 어댑터가 가장 많이 빠뜨리는 품목이다.** 본체만 받아오면 월요일이 헛걸음이 된다.

## B. 연구실을 나오기 전 현장 확인

가능하면 연구실 PC에서 30초만 확인한다. 여기서 안 되면 집에서도 안 된다.

- ☐ 전원 LED 점등
- ☐ `k4aviewer.exe` 실행 → **Depth · IR · Color 스트림이 모두 나오는가**
- ☐ 깊이 영상에 검은 구멍이 과도하게 없는가 (센서 손상 여부)

연구실 PC에 SDK가 없으면 생략하고 집에서 진행한다.

## C. 함께 확인할 부수 사항

- ☐ **대여 기간과 반납일** — 7주 일정에 맞는지
- ☐ **외부 반출 가능 여부** — 안 되면 연구실에서 촬영해야 하므로 Phase 2 장소가 바뀐다
- ☐ **악력계 / 체성분 분석기(BIA) 보유 여부** ← 계획서 부록 3번. 있으면 AWGS 근력 기준 직접 대조 가능. 연구의 최대 약점이 사라진다
- ☐ 촬영 가능한 공간 — 의자를 벽에서 떨어뜨려 놓고 3m 거리 확보 가능한지
- ☐ 좌면 높이가 일정한 견고한 의자 (바퀴 없음)

## D. 집에 와서 할 검증 (G0)

우리 PC 사양은 확인됐다. **RTX 5060 / Ryzen 5 7500F 6코어 / RAM 32GB — Body Tracking 요구사항을 충분히 넘는다.**

### 1단계 — Sensor SDK

[Azure Kinect Sensor SDK](https://learn.microsoft.com/en-us/azure/kinect-dk/sensor-sdk-download) 설치 후:

```
k4aviewer.exe
```

- ☐ Depth / IR / Color 스트림 표시
- ☐ 30fps 유지 (드롭 없음)

### 2단계 — Body Tracking SDK

[Body Tracking SDK v1.1.2](https://www.microsoft.com/en-us/download/details.aspx?id=104221) 설치 후:

```
k4abt_simple_3d_viewer.exe
```

- ☐ **32 joint 스켈레톤이 사람 위에 표시되는가** ← G0의 핵심
- ☐ 앉았다 일어서는 동작에서 추적이 끊기지 않는가

> Windows의 GPU 모드는 CUDA가 아니라 **DirectML**이 기본이다. RTX 5060은 최신 아키텍처라 구버전 CUDA 빌드와 충돌할 수 있으나, DirectML은 드라이버 기반이라 영향받지 않는다. GPU 모드가 실패하면 `CPU` 모드로 전환한다 — 느리지만 **오프라인 처리에는 문제없다**(3단계 참조).

### 3단계 — 녹화 후 오프라인 처리 (권장 방식)

실시간 추적이 필요 없다. 원본을 녹화하고 나중에 처리한다. GPU 속도가 데이터 수집을 방해하지 않게 하는 방법이다.

```
k4arecorder.exe -l 20 --depth-mode NFOV_UNBINNED -c 1080p test.mkv
```

- ☐ `.mkv` 파일 생성 확인
- ☐ 녹화 파일에 body tracking 오프라인 적용 성공

### 4단계 — Python 연동

Python으로 32 joint 좌표를 뽑는 경로는 **`pykinect-azure`** 다.

```bash
pip install pykinect-azure
```

[ibaiGorordo/pyKinectAzure](https://github.com/ibaiGorordo/pyKinectAzure) — Sensor SDK와 Body Tracking SDK를 모두 감싼다. `pyk4a`는 body tracking이 feature 브랜치에만 있어 부적합하다.

- ☐ 32 joint 3D 좌표를 프레임별로 numpy 배열로 저장
- ☐ 타임스탬프 함께 저장 ← **동기화에 필수**

## E. G0 판정 기준

| 결과 | 판정 | 대응 |
|---|---|---|
| 32 joint 스켈레톤 저장 성공 | **G0 통과** | Phase 2 진행 |
| 스트림은 되지만 body tracking 실패 | 부분 실패 | CPU 모드 재시도 → 실패 시 깊이 영상 기반 자체 처리 검토 |
| 스트림 자체가 안 됨 | **G0 실패** | 장비 교체 요청. 불가 시 계획서 §6 대응표대로 스마트폰 단독 + 공개 데이터로 설계 축소 |

G0 실패가 연구 실패는 아니다. 계획서에 이미 대응 경로를 넣어 두었다 — RQ1을 "Kinect 대비 일치도"에서 "선행 연구 재현성 및 반복측정 신뢰도"로 대체한다.

## F. 그날 함께 해두면 좋은 것

Kinect를 켠 상태에서 어차피 시간이 드니, 같이 처리한다.

- ☐ **스마트폰과 동시 촬영 1회 시험** — 본인 대상, 5회 STS. 프로토콜 리허설 겸 동기화 방식 검증
- ☐ 박수 동기화가 양쪽 데이터에서 식별되는지 확인
- ☐ 45° 각도에서 머리와 발이 두 장비 모두의 화각에 들어오는 거리 실측 → 프로토콜에 수치로 고정
- ☐ 스마트폰 60fps 고정 가능 여부 확인 (기종별로 다름)
- ☐ 의자 좌면 높이 실측

이 시험 촬영은 정식 데이터가 아니다. 프로토콜 확정용이므로 본인 대상이면 되고 동의서도 불필요하다.
