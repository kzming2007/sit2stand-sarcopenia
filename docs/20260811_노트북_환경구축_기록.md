## 1. 하드웨어 — 1호기와의 결정적 차이

```
1호기(데스크톱)  Ryzen 5 7500F 6C / RTX 5060 (NVIDIA Blackwell) / RAM 32GB
2호기(노트북)    Intel Core Ultra 5 226V 8C / Intel Arc 130V iGPU 8GB / RAM 16GB
                 Samsung 960XHA · Windows 11 Home 10.0.26200
```

**GPU가 NVIDIA가 아니라 Intel Arc 통합그래픽이다.** 이것이 유일하게 중요한 차이다.

Body Tracking SDK 공식 최소사양은 `NVIDIA GTX 1070 이상`이지만 그것은 **CUDA 경로 기준**이다.
본 프로젝트는 이미 CUDA를 버리고 **DirectML**을 쓰기로 확정했고(`20260805_환경구축_기록.md` §2),
DirectML은 DirectX 12 드라이버 기반이라 **GPU 벤더·세대에 영향받지 않는다.**
Arc 130V는 DX12를 지원하므로 원리적으로 동작한다.

> 1호기에서 CUDA 10.0 바이너리가 Blackwell을 지원하지 않아 내린 결정이,
> 2호기에서는 애초에 CUDA가 존재하지 않는 상황을 그대로 흡수했다. 결정이 두 번 값을 했다.

**2026-08-11 실측 확인됨 (§7).** Arc 130V에서 `--cpu` 폴백 없이 DirectML로 트래커가 기동했다.
속도는 5.9 fps / 지연 153ms 로 1호기(8.0 fps / 118ms)보다 느리지만, 본 연구는
`k4arecorder` 녹화 후 오프라인 처리이므로 **수집을 제약하지 않는다.**

### USB

USB 3.x 루트 허브 2개 정상(`Intel USB 3.20 xHCI` × 2, `USB4 Host Router`).
1호기 G0 실패의 원인이었던 **USB 2.0 케이블 문제는 여기서도 동일하게 적용된다** —
반드시 `USB 3.0 / 5Gbps` 표기 케이블을 쓰고, **허브·독·연장선을 경유하지 않는다.**

노트북은 포트 수가 적어 독을 쓰기 쉬운데, 그것이 정확히 1호기 1차 시도가 실패한 경로다.
본체 USB-A 포트에 직결할 것.

## 2. 설치한 것

### Sensor SDK v1.4.2

GitHub 릴리스에는 asset이 없고 `docs/usage.md` 가 Microsoft 다운로드 서버를 가리킨다.

```
https://download.microsoft.com/download/d/c/1/dc1f8a76-1ef2-4a1a-ac89-a7e22b3da491/Azure%20Kinect%20SDK%201.4.2.exe
```

**WiX Burn 번들이라 무인 설치가 된다** (1호기 기록에는 없던 사실).

```powershell
& 'Azure Kinect SDK 1.4.2.exe' /install /quiet /norestart   # 관리자 권한
```

설치 결과 `C:\Program Files\Azure Kinect SDK v1.4.2\` — `k4aviewer.exe`,
`k4arecorder.exe`, `AzureKinectFirmwareTool.exe`, `k4a.dll`, `depthengine_2_0.dll` 확인.

### Body Tracking SDK 1.1.2

`k4abt_sdk/` 는 재배포 금지라 저장소에 없다. NuGet에서 다시 조립했다.
**2026-08-11 기준 세 패키지 모두 NuGet에 살아 있다.** 절차는 `k4abt_sdk/README.md`.

CUDA 관련 4개 파일(약 320MB)은 1호기와 동일하게 제외했다.

### Python

전역 환경이 이미 numpy 2.4.6 / pandas 3.0.3 이라 **프로젝트 전용 `.venv`** 를 만들었다.
(`.venv` 는 자체 `.gitignore`(`*`)를 갖고 있어 git에 잡히지 않는다.)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install numpy pandas scipy scikit-learn `
    opencv-python pykinect-azure mediapipe xgboost shap
```

## 4. 주의 — 패키지 버전이 1호기와 다르다

pip 최신 해석 결과라 1호기 기록과 차이가 있다. **재현 수치에 영향을 줄 수 있다.**

| 패키지 | 1호기 | 2호기 |
|---|---|---|
| Python | 3.13.7 | **3.13.5** |
| numpy | 1.26.4 | **2.4.6** |
| opencv-python | 4.7.0 | **5.0.0.93** |
| mediapipe | (미기록) | 1.0.0 |
| pandas / scipy / scikit-learn | (미기록) | 3.0.5 / 1.18.0 / 1.9.0 |
| pykinect-azure | 0.0.4 | 0.0.4 ✅ |

numpy 1.x → 2.x, opencv 4 → 5, pandas 2 → 3 은 모두 **메이저 변경**이다.
G1 재현이 `4.68 × 10⁻⁹ 초` 수준의 정밀도를 주장하고 있으므로,

- **최종 보고서에 넣을 수치는 한 대에서 산출한다.** 두 대의 결과를 섞지 않는다
- 노트북은 **Kinect 수집·MediaPipe 실영상 처리·문서 작업**에 쓰고,
  공개 데이터 재현(G1/G4) 수치는 1호기 기준을 유지하는 편이 안전하다
- 굳이 맞추려면 1호기에서 `pip freeze > requirements.txt` 를 떠서 커밋하고
  양쪽을 그 파일로 고정한다

## 7. G0 재확인 — 2026-08-11, 노트북 1차 시도

### 판정: **통과.** 1호기와 동일하게 계획서 §3.1 G0 기준 충족.

```
날짜/시각      : 2026-08-11
전원 경로      : 돼지코 + MS 1624
USB 포트       : 노트북 본체 USB-A 직결
1단계 감지     : 성공 — Index:0  Serial:000292113912  Color:1.6.110  Depth:1.6.80
3단계 처리모드 : GPU DirectML  (--cpu 폴백 불필요)
3단계 검출률   : 100 / 100 프레임
3단계 처리속도 : 5.9 fps,  tracker.update 지연 중위 153.1 ms
joint 수       : 32   shape (32, 8)
depth 건너뜀   : 0
오류 메시지    : 없음. 카메라 시작 재시도도 발생하지 않음
저장           : scratch/g0_skeleton.npy
```

**1호기가 4차 시도까지 걸린 것을 2호기는 1차에 통과했다.** 배치 조건(1m 높이 / 2~2.5m /
역광 차단)이 이미 규명돼 있었기 때문이다. 진단 기록을 남긴 것이 그대로 회수됐다.

### 좌표 타당성 — 1호기와 교차 검증

동일 피험자·동일 장비이므로 두 기기의 신체 치수가 맞아야 한다.

| 항목 | 2호기 | 1호기 | 차이 |
|---|---|---|---|
| 좌우 고관절 간격 | 175.1 mm | 171.5 mm | 3.6 mm |
| 코–발 수직거리 | 1522.3 mm | 1531 mm | 8.7 mm |
| 촬영 거리 z | 약 1.87 m | 약 1.97 m | (배치 차이) |

y가 위에서 아래로 단조 증가한다: 코 −774.6 → 목 −618.2 → 골반 −76.4 →
무릎 327 → 발목 696 → 발 742. 좌우 대칭도 정상이다.

**두 독립 환경이 3~9mm 안에서 일치한다.** 노트북 조립본이 데스크톱과 동등하다는 증거다.

### DirectML — Arc 130V 확인

CUDA를 버린 결정이 두 번째로 값을 했다. 1호기에서는 CUDA 10.0 바이너리가
Blackwell을 지원하지 않아서였고, 2호기에서는 NVIDIA GPU가 아예 없기 때문이다.
DirectML은 두 경우 모두를 벤더 중립적으로 흡수했다.

속도만 iGPU 몫으로 떨어진다(5.9 fps vs 8.0 fps). 오프라인 처리라 무관하다.
