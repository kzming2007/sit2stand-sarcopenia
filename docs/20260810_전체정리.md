## 1. 이 연구가 무엇인가

### 목표

스마트폰 카메라 하나로 5회 의자 일어서기(5STS)를 분석해 근감소증 위험을 **선별**한다. 단, 그 전에 **어떤 지표를 어디까지 믿을 수 있는지** 정량적으로 규명한다.

### 왜 이 주제가 성립하는가

근감소증 진단은 세 축을 조합한다 — 근육량(DXA·BIA), 근력(악력계), 신체기능(보행속도·의자 일어서기). 앞의 둘은 전용 장비가 필요하지만 **신체기능은 도구 없이 측정 가능하다.**

결정적으로 **AWGS 2019가 `5회 의자 일어서기 ≥ 12초`를 저신체기능 기준으로 명시한다.** 국제 합의 문서에 초시계로 재는 임계값이 들어 있다는 뜻이다. 여기에 컴퓨터 비전을 결합하면 측정 자체를 자동화·객관화할 수 있다.

AWGS 2019 기준 세 숫자:
- 악력 남 <28kg, 여 <18kg
- 6m 보행속도 <1.0 m/s
- **5STS ≥ 12초**

`possible sarcopenia`는 근력 저하 **또는** 신체기능 저하 하나만 있어도 성립한다. 확진에는 근육량이 필요하다. **본 연구는 세 번째 축만 다루므로 `진단`이 아니라 `선별`이다.**

### 기반 논문

**Boswell et al. (2023), npj Digital Medicine.** 미국 35개 주 405명이 가정에서 스마트폰으로 5STS를 자가 촬영, OpenPose 2D 자세추정으로 운동학 지표를 산출해 골관절염·PROMIS 건강점수와의 연관을 분석했다.

이 논문에서 확인된 핵심 사실:

| 항목 | 값 | 의미 |
|---|---|---|
| 검사 시간 vs 마커 기반 모션캡처 | **r = 0.997** | 시간은 2D 영상이 거의 완벽하게 잰다 |
| 체간각 vs 요추 굴곡 | r = 0.583 | 각도는 그렇지 않다 |
| 체간각 vs 요추 측굴 | r = 0.702 | |
| 체간 각가속도 | r = 0.556 | 미분할수록 나빠진다 |
| 실험실 검증 표본 | n = 11 (평균 27.7세) | 우리 규모의 선례 |

**이 논문은 머신러닝 모델을 만들지 않았다.** 상관·회귀분석만 했다. 예측 모델링이 미개척 영역으로 남아 있고, 그게 우리 자리다.

**후속 연구 Chan et al. (2026), Communications Medicine.** 309명 측면 STS 영상 2,063건 + 딥러닝으로 무릎 골관절염 판별 **AUC 0.776**. 두 가지를 시사한다 — 각속도에 신호가 있고, **2,063건 딥러닝으로도 0.78이므로 405명에서 0.9 이상은 비현실적**이다.

## 2. 초안에서 무엇을 바꿨고 왜

2026-06-29 제출한 초안(v1)을 공개 데이터 직접 검증 후 네 곳 수정했다. 확정본은 `20260728_연구계획서_수정본_v2.md`.

### 2.1 Azure Kinect는 Ground Truth가 아니다 → 기준 비교 장비

Kinect도 마커 없는 추정 장비이고 자체 오차가 있다. 특히 고관절과 가려진 분절이 취약하다(ICC 0.64 수준). 관측된 불일치는 **두 장비 오차의 합**이므로 스마트폰만의 오차로 해석할 수 없다.

분석 프레임을 `정확도 검증` → **`방법 비교(method comparison)`** 로 바꿨다. Bland-Altman을 추가했다.

여기서 인용 문헌 하나를 정정했다. **Jo et al. (2022) Sensors는 스쿼트·런지·리치를 시험했고 sit-to-stand는 포함하지 않았다.** 초기 문서 두 개에 이 수치가 STS 검증인 것처럼 적혀 있었다. v2에서 정정하고, 오히려 **한계 4번(STS에 대한 Kinect 검증 자료 부족)** 으로 승격했다 — 그 공백이 우리 기여 지점이 된다.

### 2.2 CoM 기반 STS Power → Alcazar(2018) 검증식

단일 2D 45° 뷰로는 질량을 얻을 수 없고 CoM 수직변위는 원근 왜곡을 받는다. Alcazar 식은 **체중·신장·의자높이·5STS 시간** 넷만 필요하고 다리 길이 실측이 불필요하다. 60–93세 718명에 3종 장비로 검증됐다.

```
F = 0.9 × 체중 × g                 (정강이·발은 상승하지 않음)
d = 0.5 × 신장 − 의자 좌면 높이
v = d / (1회 반복시간 중 신축 국면)
P = F × v ,  상대파워 = P / 체중 (W/kg)
```

**핵심은 이것이다. 영상이 담당하는 입력은 `시간` 하나이고, 시간은 2D 영상이 가장 정확하게 재는 지표다(r=0.997).** 나머지 셋은 줄자와 체중계로 잰다. 반면 CoM 기반은 2D가 가장 못하는 것(3D 위치와 질량)을 요구한다. 가장 약한 고리를 가장 강한 고리로 바꾼 교체다.

### 2.3 근감소증 위험군 분류 → 저신체기능 선별의 증분가치 (가장 중요)

`dataClean.csv`를 직접 내려받아 열 이름을 전수 확인한 결과, **사지근육량·악력·보행속도·근감소증 진단이 하나도 없다.** 따라서 근감소증 분류기는 원리적으로 학습 불가능하다.

질문을 이렇게 바꿨다.

> 초시계로는 얻을 수 없는 동작 품질 지표를 5STS 시간에 추가하면 예측이 개선되는가?

계단식 모델로 순환논리를 차단한다.

| 모델 | 입력 | 성격 |
|---|---|---|
| M0 | Age, Sex, BMI | 인구통계 |
| M1 | + 5STS 총 시간 | **초시계로 얻을 수 있는 것** |
| M2 | + 비시간 운동학 | **영상만 가능, 총 시간과 독립** |
| M3 | + 시간 분해 지표 | 영상만 가능, 총 시간과 중복 |

표기는 `근감소증 진단`이 아니라 **`저신체기능 선별`** 로 고정한다. AWGS 5STS≥12초는 국제 합의 기준이므로 **정당한 대리지표**다.

### 2.4 데이터 수집보다 논문 재현을 먼저

특징 추출 코드가 검증되지 않은 상태로 자체 데이터를 수집하면 코드 수정 시 전량 재분석이다. 재현은 공개 코드·데이터로 하므로 비용이 거의 없다. **이 결정은 성과를 냈다** — §3.1.

### 3.2 Phase 4 / G4 — 증분가치 1차 분석 (2026-08-05)

**분석 전에 검증 게이트를 통과했다.** 선행 논문이 보고한 상관 5개를 대조했다.

| 상관 | 본 분석 | 논문 |
|---|---|---|
| time ↔ GPH_TScore | **−0.200** | −0.20 |
| time ↔ BMI | **+0.203** | +0.20 |
| time ↔ Age | **+0.350** | +0.35 |
| time ↔ OA_check | +0.177 | +0.18 |
| trunk_lean_max ↔ OA_check | +0.164 | +0.18 |

전부 ±0.05 이내다. **따라서 아래 결과는 파이프라인 오류가 아니다.**

**결과 세 가지 — 선형 모델과 RandomForest 양쪽에서 재현됨**

| 발견 | Ridge/Logistic | RandomForest |
|---|---|---|
| ① 5STS 시간은 신체건강(GPH) 예측에 **기여한다** | ΔR² **+0.0142** [+0.008, +0.020] 유의 | ΔR² **+0.0422** [+0.025, +0.060] 유의 |
| ② 비시간 운동학은 시간 위에 **더하지 못한다** | −0.0127 | +0.0011 |
| ③ 시간을 빼면 운동학만으로 AWGS 임계값 **판별된다** | AUC 0.628 → **0.780** (Δ+0.153) | AUC 0.608 → **0.831** (Δ+0.223) |

②의 표현에 주의. 선형에서는 **떨어졌지만** Forest에서는 **변화 없음**이었다. 선형에서의 하락은 405명에 16개 특징을 넣은 과적합으로 설명된다. 정확한 진술은 **"기여하지 않는다"** 이며 "해롭다"가 아니다.

②와 ③이 모순처럼 보이지만 아니다. **운동학 지표는 "느린 사람"을 식별하는 정보는 갖지만, 시간을 이미 아는 상태에서 건강 결과를 추가로 설명하지 못한다.** 시간의 **대체** 지표이지 **보완** 지표가 아니다.

계획서에 사전에 밝힌 대로 ②는 실패가 아니다. 결론은 **"2D 영상의 가치는 동작 품질 지표보다 시간 측정의 자동화·객관화에 있다"** 가 된다.

③이 Forest에서 더 강한 것(+0.223 vs +0.153)은 관계가 **비선형**일 가능성을 시사한다.

**공개 데이터의 구조적 한계도 드러났다.** OA 분석에서 M0(인구통계만) AUC가 이미 0.9147이었다.

```
Age 단독 ROC-AUC(OA) = 0.9176
OA 양성자 평균 67.0세  /  음성자 34.9세     (32년 차이)
```

이 코호트의 OA 환자는 사실상 "고령자"와 동일해서 다른 특징이 기여할 여지가 없다. **영상 특징의 한계가 아니라 데이터 구조의 한계다.**

50세+ 하위군(n=106)은 R²가 전부 음수 — 표본 부족으로 분석 불가. 낙상(양성 34명)도 어느 모델로도 예측되지 않는다(AUC 0.55~0.63, SD 0.11~0.15).

**부수 소득 둘**
- Alcazar 상대파워 **3.44 ± 1.18 W/kg**. 평균 37세 표본이니 75세 참조치(남 2.6±0.7 / 여 2.0±0.6)보다 높은 게 정상 — 식 구현이 맞다는 방증
- **`trunk_lean_range_mean`(R=+0.186)이 `trunk_lean_max`(+0.164)보다 강하다.** 논문은 최대값을 주 지표로 썼는데 가동 범위가 더 나을 수 있다. Phase 3 검증 지표에 추가할 것
- 좌우 비대칭 3개는 전부 무의미(|R|<0.04). 45° 시야에서 한쪽 다리가 가려지는 문제와 일치

```
Azure Kinect Sensor SDK v1.4.2  (GitHub 릴리스 MSI)

```

**Body Tracking SDK의 MSI 배포가 중단됐다.** 공식 문서 링크는 404이고 Sensor SDK 저장소는 2024-08-22 아카이브됐다. NuGet에서 필요한 파일만 추출해 `k4abt_sdk/bin/`에 조립했다(227MB, 재배포 불가라 git 제외).

**CUDA 대신 DirectML을 쓴다.** NuGet의 CUDA 의존성은 CUDA 10.0 / cuDNN 7(2019년)이라 RTX 5060(Blackwell)을 지원하지 않는다. Windows GPU 기본 경로가 DirectML이고 드라이버 기반이라 세대 영향이 없다. **2026-08-09 실측으로 DirectML 트래커 기동을 확인했다** — 이 결정이 옳았음이 검증됐다.

## 4. 발견한 함정 7개

모르면 조용히 틀리는 것들이다. 후임자가 반드시 다시 부딪힌다.

### ① `dataClean.csv` 와 `dataClean_text.csv` 는 다른 버전

| | 행 | 열 | 5STS 평균 |
|---|---|---|---|
| `dataClean.csv` | 405 | 738 | **11.40초** ← 논문과 일치 |
| `dataClean_text.csv` | 405 | 700 | 11.13초 |

**405행 중 47행의 `time` 값이 다르다.** 섞어 쓰면 조용히 틀린다.
**규칙**: 분석은 `dataClean.csv` 하나만. `_text`에서는 `subjectid` 열만 가져온다.

### ② `dataClean.csv` 의 subjectid 는 전부 `'0'` (익명화)

원본 8자 ID는 `_text`에만 있다. 다행히 `framerate`·`Age`가 405/405 행 단위로 일치해 **행 순서가 같다.** 행 인덱스로 복원한다.

```python
dc['subjectid'] = pd.read_csv('stats/dataClean_text.csv')['subjectid'].values
```

### ③ `Height` 는 인치, `Weight` 는 파운드

BMI 역산으로 확인(70in / 168lb → 24.1). cm·kg로 착각하면 Alcazar 파워가 전부 틀린다.

### ④ 국면 분할 시간은 총 시간의 분해다 — 순환논리 유발

```
corr( (time_sit2stand + time_stand2sit) × 5 , time ) = 0.9724
corr( time_stand2sit , time ) = +0.91
corr( time_sit2stand , time ) = +0.78
corr( time_sd        , time ) = +0.60
```

이를 AWGS(=`time ≥ 12`) 판별에 쓰면 **답을 입력에 넣는 것**이다. 실제로 1차 실행에서 AUC가 **0.964**로 나왔고, 분리 후 정상값 0.780을 얻었다.

스크립트에서 `QUALITY_KINEMATIC` / `QUALITY_TEMPORAL` 로 분리해 두었다. **이 발견은 최종 보고서의 방법론 기여로 쓸 수 있다.**

### ⑤ `videos/np` 다운로드는 629/767 로 불완전하다

Google Drive 대용량 폴더 zip이 조용히 잘린다. 코호트 81명 누락. **단 처리 실패는 0건이고 Phase 4에 영향 없다.** 재다운로드는 자체 파이프라인 전수 검증 시에만 필요하며, 웹 zip 대신 `rclone` 권장.

### ⑥ Jo et al. (2022) 는 sit-to-stand 를 시험하지 않았다

Azure Kinect 검증 문헌으로 인용하는데 실제 대상은 **스쿼트·런지·리치**다. 초기 문서 두 개(`연구프로세스_재구성_v1`, `도메인지식_입문_v1`)에 STS 검증인 것처럼 적혀 있다. **v2 계획서에서 정정했다.**

### ⑦ `synchronized_images_only` 기본값이 `False` 다 — 트래커가 죽는다

`pykinect.default_configuration`의 기본값이 `False`이면 capture에 color만 담기고 depth가 빠질 수 있는데, body tracker는 매 capture에 depth를 요구한다.

```
k4a_image_t_get_context(). Invalid k4a_image_t 0000000000000000
[K4ABT] Get depth buffer from the capture handle failed!
-> Body tracker capture enqueue failed!
```

**수정**: `config.synchronized_images_only = True`. 2026-08-09 실측으로 30/30 프레임에 depth가 들어옴을 확인. `verify_kinect.py`에 반영 완료.

## 5. 장비 분투기 (G0)

이 부분이 가장 오래 걸렸다. 기록해 두면 같은 함정을 반복하지 않는다.

### 타임라인

| 날짜 | 시도 | 결과 |
|---|---|---|
| 08-05 | 장비 수령. 정품 전원 어댑터 없어 돼지코 구매 | 전원은 들어왔으나 **접점 고정 불량**으로 반품 |
| 08-08 | 2차 시도 | **USB 케이블 원인 규명** |
| 08-09 | USB 3.0 A-to-C 케이블로 3차 | **1·2단계 통과.** 3단계는 촬영 조건만 남음 |

### 08-08 — 케이블이 원인이라는 진단

Kinect 뒷면 LED **흰색 깜빡임** = MS 공식 표의 `전원은 켜졌으나 USB 3.0 데이터 연결 없음`.

내부 엔드포인트 5개 중 **High Speed만 붙고 SuperSpeed는 전부 실패**했다.

| PID | 구성요소 | 속도 | 결과 |
|---|---|---|---|
| `097B` | USB 2.0 Hub | HS | ✅ |
| `097E` | Microphones | HS | ✅ |
| `097A` | USB3.1 Gen2 Hub | SS | ❌ |
| `097C` | Depth 카메라 | USB3.0 | ❌ |
| `097D` | Color 카메라 | USB3.0 | ❌ |

케이블 2개 × 포트 3곳(그중 2회는 `ROOT_HUB30` 직결)에서 동일 실패 → 경로 배제. 전원 부족도 배제(LED 흰색, 카메라가 열거를 시도함). PC USB 3.0도 정상(다른 SuperSpeed 허브 열거 확인).

**결론: 보유 케이블 2개가 모두 USB 2.0 전용(충전용). SuperSpeed 신호선 4가닥이 물리적으로 없다.**

### 08-09 — 해결

USB 3.0 A-to-C 케이블을 **PC 후면 USB-A 포트에 직결**하자 즉시 해결.

```
Index:0   Serial:000292113912   Color:1.6.110   Depth:1.6.80
엔드포인트 5개 전부 정상, 오류 장치 0개
30 프레임 연속 depth=True color=True ir=True
```

**돼지코는 결국 불필요했다.** MS 1624는 USB-A 출력 소켓이 달린 평범한 5V 충전기이고 동봉 전원 케이블이 `USB-A → 배럴`이다. 따라서 **한국 플러그 5V 2A USB 충전기 아무거나로 대체된다.**

### 3단계 — 인체 검출 0의 원인

파이프라인은 완주하나(100프레임, 트래커 오류 0, 8.7fps, 지연 중위 106.5ms) 인체 검출이 0이었다. Color/Depth 스냅샷으로 원인을 특정했다. **장비가 아니라 촬영 조건이다.**

| # | 문제 | 근거 |
|---|---|---|
| 1 | **하반신이 책상에 잘림** | 앉은 자세 + 책상이 프레임 하단 차단. 무릎·발목·발 = `STS_JOINTS` 핵심 관절 전부 부재 |
| 2 | **거리 근접** | depth 중위 **1531mm**. 권장 1.5~3m의 하한 |
| 3 | **역광이 depth 파괴** | 유리문 햇빛이 ToF IR 센서 포화. depth 유효화소 **21%**, 3000–3860mm 구간 **0.0%** |

**조치**: ① 일어서서 2~2.5m 뒤로 ② 카메라를 빼거나 높여 발까지 프레임에 ③ 유리문 커튼 차단.

③은 **Phase 2 본촬영에도 적용된다.** 계획서 §3.3의 "밝은 실내"는 **확산광**을 뜻하며 직사광 역광이 아니다. 촬영 장소를 창·유리문을 등지지 않게 배치해야 한다.

### 재개 명령

```bash
python scripts/verify_kinect.py --delay 30
```

카운트다운 동안 카메라 앞에 선다. 실패 시 `--cpu`.

> 8.7 fps / 106ms는 GPU치고 느려 CPU 폴백 가능성이 있다. 오프라인 처리 방식이라 수집을 제약하지 않으므로 G0 통과 후 확인한다.

## 6. 남은 일과 위험

### Phase 0 잔여 (행정)

| # | 항목 | 영향 |
|---|---|---|
| 1 | **IRB 심의 대상 여부 및 피험자 범위** | **Phase 2를 막는 유일한 행정 항목** |
| 2 | **착수일 확정** | 7주 일정이 상대 주차로만 존재 |
| 3 | **악력계·BIA 보유 확인** | 있으면 AWGS 근력 기준 직접 대조 가능 → **"대리지표만 쓴다"는 최대 약점이 사라진다** |
| 4 | **장비 반납 기한 확인** | 대여 장비. 기한 내 G0 확정 필요 |
| 5 | Alcazar(2018) 원문 확보 | 신축 국면 비율·계수 확정 |
| 6 | 스마트폰 60fps 고정 가능 여부 | 각속도 지표 품질에 직결 |

**7주 내 IRB 승인 후 고령자 신규 모집은 불가능하다고 전제했다.** 피험자는 연구팀 + 서면 동의 성인 자원자로 한정하고 고령층 검증은 후속 과제로 명시한다. 선행 논문의 실험실 검증도 n=11, 평균 27.7세였다.

### 알려진 한계 (최종 보고서에서 삭제하지 말 것)

1. **표본 연령 편중** — 20대 집중. 근감소증 주 대상인 고령층 검증 불가
2. **표본 규모** — 30 trial 목표. ICC 신뢰구간이 넓다
3. **Azure Kinect 자체 오차** — 정답이 아니다. 고관절·가려진 분절 취약
4. **STS에 대한 Kinect 검증 자료 부족** — 인용 가능한 값이 스쿼트·런지 기반
5. **2D 투영 오차** — 45° 시야는 측면·정면 혼합, 순수 해부학적 평면이 아니다
6. **MediaPipe(33) vs OpenPose(25)** — 골반 정의가 달라 논문 수치와 직접 비교 불가
7. **근감소증 라벨 부재** — 대리지표 사용. 진단이 아니다
8. **공개 데이터 불균형·편중** — OA 양성 30명, 65세+ 46명
9. **연령 교란** — OA 분석에서 Age 단독 AUC 0.918로 기저선 포화
10. **선별 도구의 한계** — 의료기기 인증 없음
