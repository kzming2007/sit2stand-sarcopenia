## 한 문장 연구 질문

> 단일 RGB 기반 5회 Sit-to-Stand 분석에서 어떤 시간·자세 특징을 신뢰할 수 있으며, 이 특징이 총 수행 시간 외에 건강 관련 평가에 추가 정보를 주는가?

이 질문은 경진대회 결과물 기준이다. 학술연구장학에서는 이후 촬영 조건과 기준 장비 비교를 통해 측정 신뢰도를 추가 검증한다.

## 현재 결론

### 확인됨

- 공개 STS 분석의 주요 특징 계산을 독립 재현했다.
- 공개자료에서 총 수행 시간은 일반적 신체건강 점수 설명에 소폭 기여했다.
- 현재 구성한 비시간 자세 요약 특징은 수행 시간 위에서 안정적인 추가 가치를 보이지 않았다.
- 공개 코드의 산출 정의와 필터를 정정해도 주요 판정 방향은 유지됐다.
- 반복 수 기반 자동 평활 강도 선택은 완화 기준 통과율을 87.7%에서 93.4%로 높였다.
- 직접 촬영한 동일인 영상 3개에서 영상 입력부터 pose, 국면과 특징 출력까지 실행됐다.
- Azure Kinect에서 32개 관절 좌표를 획득하는 G0를 통과해 동시 촬영 준비가 가능해졌다.

### 해석 제한

- `GPH_TScore`는 일반적인 자기보고 신체건강 점수이며 근감소증 진단 label이 아니다.
- `5STS 12초 초과 여부`는 수행 시간에서 만든 기준이므로 독립적인 임상 진단 성능으로 표현하지 않는다.
- 자동 QC는 반복 수를 맞추는 비율을 높였지만 전체 경계 정확도나 사람 검수 제거를 입증하지 않았다.
- 직접 촬영 결과는 동일인 예비실험이며 성능 검증 자료가 아니다.
- Kinect는 방법 비교 장비이며 ground truth로 표현하지 않는다. 현재는 G0만 통과했고 스마트폰과의 지표 비교 결과는 아직 없다.

### 보류

- IRB 회신 후 Kinect와 스마트폰 동시 촬영에 기반한 지표별 일치도
- 촬영 조건 변화에 대한 정식 안정성 검증
- 반복 시간축 특징 `R0~R2`의 GPH 추가 가치 비교
- 다른 공개 데이터셋과의 통합 분석

## 경진대회 기여 구조

1. **재현:** 공개 코드와 pose trajectory에서 STS 시간·각도·속도 특징 계산을 재현했다.
2. **검증:** 공개 코드의 산출 정의 오류와 필터 차이가 결론에 미치는 영향을 비교했다.
3. **분석:** 총 수행 시간과 비시간 자세 특징이 건강 관련 결과에 주는 추가 정보를 구분했다.
4. **개선:** 고정 평활 강도 대신 프로토콜 반복 수 기반 후보 선택과 실패 상태 출력을 추가했다.
5. **적용:** 실제 스마트폰 영상에서 전체 파이프라인이 동작하는 예를 확인했다.
6. **방법 비교:** IRB 회신 후 스마트폰과 Kinect에서 공통으로 계산되는 지표의 일치도를 평가한다.
7. **한계 제시:** 자동 처리 실패와 Kinect도 추정 장비라는 한계를 결과와 함께 제시한다.

## 동기에게 공유할 내용

지금 깃헙 main에는 공개자료 재현, 건강 관련 결과 분석, 코드 변형 검증, 실영상 MediaPipe 실행이랑 자동 국면 QC까지 올라가 있음. Kinect도 두 환경에서 32관절 획득까지 통과해서 장비 준비는 된 상태고, 동시 촬영은 IRB 회신을 기다리고 있음. 공개자료에서는 총 수행 시간은 신체건강 점수 설명에 조금 도움 됐는데, 시간 외 자세 요약 특징을 추가했을 때 안정적인 개선은 확인되지 않았음. 대신 고정 평활값보다 반복 수 기반 자동 선택이 국면 QC 통과율을 87.7%에서 93.4%로 높였고 실패나 모호한 경우도 따로 표시할 수 있게 됨. 경진대회는 신뢰 가능한 특징 선별이 중심이고, IRB 회신이 오면 스마트폰-Kinect 비교를 주결과로 추가하면 됨. 회신이 늦어도 공개자료 분석, QC 개선, 실제 스마트폰 영상 적용으로 보고서 초안은 먼저 만들 수 있을 듯.
