## 2. Body Tracking SDK — MSI 배포 중단과 대응

### 문제

Microsoft가 Body Tracking SDK의 **MSI 설치 파일 배포를 중단했다.**

- 공식 문서(`learn.microsoft.com/.../body-sdk-download`)의 msi 링크 → **404 "no longer available"**
- 1.1.2뿐 아니라 다른 버전도 동일
- Azure Kinect Sensor SDK 저장소는 2024-08-22 아카이브됨

Sensor SDK(v1.4.2)는 GitHub 릴리스에서 정상 배포되므로 영향이 없다. Body Tracking만 문제였다.

### 대응 — NuGet에서 조립

NuGet 패키지는 유지되고 있음을 확인해 필요한 파일만 추출했다.

| 패키지 | 버전 | 추출한 파일 |
|---|---|---|
| `microsoft.azure.kinect.bodytracking` | 1.1.2 | `k4abt.dll`, `k4abt.lib`, onnx 모델 2종, 헤더 3종 |
| `microsoft.azure.kinect.bodytracking.onnxruntime` | 1.10.0 | `onnxruntime.dll`, **`directml.dll`**, `onnxruntime_providers_shared.dll` |
| `microsoft.azure.kinect.bodytracking.dependencies` | 0.9.1 | `vcomp140.dll` (OpenMP 런타임) |

다운로드 엔드포인트:

```
https://api.nuget.org/v3-flatcontainer/{패키지}/{버전}/{패키지}.{버전}.nupkg
```

`.nupkg`는 zip이며 바이너리는 `lib/native/amd64/release/`, 모델은 `content/` 아래에 있다.

### CUDA 패키지를 제외한 근거

NuGet에는 CUDA 의존성 패키지도 있으나 **의도적으로 제외했다.**

| 패키지 | 내용 | 문제 |
|---|---|---|
| `...dependencies` 0.9.1 | `cublas64_100.dll`, `cudart64_100.dll` | **CUDA 10.0** (2019년) |
| `...dependencies.cudnn` 0.9.1 | `cudnn64_7.dll` (350MB) | **cuDNN 7** |

이 PC의 GPU는 **RTX 5060(Blackwell)** 이다. CUDA 10.0 바이너리는 이 세대를 지원하지 않으므로 CUDA 경로는 애초에 쓸 수 없다.

**대신 DirectML을 사용한다.** Windows에서 `K4ABT_TRACKER_PROCESSING_MODE_GPU`의 기본 실행 경로가 CUDA가 아니라 DirectML이며, DirectML은 DirectX 12 드라이버 기반이라 GPU 세대에 영향받지 않는다. `directml.dll`이 onnxruntime 패키지에 포함되므로 별도 설치가 필요 없다.

결과적으로 **CUDA/cuDNN 590MB를 받지 않고도 GPU 추론이 가능하다.**

실패 시 `K4ABT_TRACKER_PROCESSING_MODE_CPU`로 전환한다. 본 연구는 `k4arecorder`로 원본을 녹화한 뒤 오프라인 처리하는 방식이므로 추론 속도가 데이터 수집을 제약하지 않는다.

### 상실한 것

MSI에만 있던 **샘플 뷰어 `k4abt_simple_3d_viewer.exe`를 쓸 수 없다.**
대체 검증 도구로 `scripts/verify_kinect.py`를 작성했다.

## 3. 설치 과정에서 막힌 지점

### PowerShell 실행 정책 (Restricted)

`install_to_program_files.ps1` 실행 시:

```
PSSecurityException: 이 시스템에서 스크립트를 실행할 수 없으므로 ... 파일을 로드할 수 없습니다.
```

원인 진단 결과:

```
MachinePolicy   Undefined
UserPolicy      Undefined
Process         Undefined
CurrentUser     Undefined
LocalMachine    Undefined
```

모든 범위가 `Undefined`이므로 Windows 클라이언트 기본값 **`Restricted`** 가 적용된다.

**중요: 이는 관리자 권한과 무관하다.** 실행 정책은 권한 상승 여부와 별개로 `.ps1` 파일 로드를 차단한다. 관리자 PowerShell에서도 동일하게 실패한다. 파일에 Zone.Identifier(인터넷 다운로드 차단 표시)는 없었으므로 순수하게 정책 문제였다.

**해결**: `.ps1`을 거치지 않고 명령을 직접 실행했다. 실행 정책은 스크립트 파일에만 적용되므로 대화형 명령은 영향받지 않는다.

```powershell
$dst='C:\Program Files\Azure Kinect Body Tracking SDK\sdk\windows-desktop\amd64\release\bin'
New-Item -ItemType Directory -Force $dst | Out-Null
Copy-Item 'D:\claude\sit2stand-sarcopenia\k4abt_sdk\bin\*' $dst -Force -Exclude 'include'
```

관리자 권한은 Program Files 쓰기에 필요하므로 여전히 요구된다.

> 대안: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`를 먼저 실행하면 해당 창에서만 정책이 완화된다. 창을 닫으면 원복되며 시스템 설정은 변경되지 않는다.

## 4. 검증 결과

### 파일 배치 확인

```
[OK] k4a.dll                        Sensor SDK
[OK] k4arecord.dll                  Sensor SDK
[OK] k4abt.dll                      Body Tracking
[OK] directml.dll                   Body Tracking
[OK] onnxruntime.dll                Body Tracking
[OK] vcomp140.dll                   Body Tracking
[OK] dnn_model_2_0_op11.onnx        Body Tracking
[OK] dnn_model_2_0_lite_op11.onnx   Body Tracking
```

### DLL 로드 시험 (장비 불필요)

```python
import pykinect_azure as pykinect
pykinect.initialize_libraries(track_body=True)   # -> 성공
```

**이 호출이 성공한 것이 핵심 증거다.** `k4a.dll`과 `k4abt.dll`을 모두 로드하며, `k4abt.dll`은 `onnxruntime.dll` → `directml.dll` → `vcomp140.dll` 의존성 체인을 요구한다. 따라서 **조립이 누락 없이 완결되었음이 확인된다.**

상수 확인:

```
K4ABT_JOINT_COUNT = 32
K4ABT_TRACKER_PROCESSING_MODE_GPU_DIRECTML = 4
```

계획서 §3.3이 전제한 32 joint 구성과 일치한다.

### 아직 검증되지 않은 것

DLL 로드는 확인했으나 **다음은 장비 연결 후에만 확인 가능하다.**

- 카메라 스트림 (Depth / IR / Color)
- 실제 32 joint 좌표 획득 = **G0**
- DirectML GPU 모드가 RTX 5060에서 실제 동작하는지
- 추론 처리 속도

`scripts/verify_kinect.py`는 하드웨어 없이 작성되었으므로 첫 실행 시 경로·API 오류 가능성이 있다. **오류 메시지를 그대로 기록할 것.**

## 5. 하드웨어 구성 (2026-08-05 수령)

| 품목 | 상태 |
|---|---|
| Azure Kinect DK 본체 | ✅ |
| 전원 어댑터 Microsoft Model 1624 — Input 100-240V 0.3A 50/60Hz, **Output 5.2V 2.5A (13W)** | ✅ 규격 적합 |
| 전원 케이블 | ✅ |
| 데이터 케이블 (PC 연결용) | ✅ |
| **돼지코 (미국식 납작 2핀 → 한국식 둥근 2핀)** | ⬜ **미확보** |

어댑터 입력이 **100-240V 프리볼트**이므로 한국 220V에 직결 가능하다. **변압기는 불필요하며 사용해서는 안 된다.** 플러그 형상 변환만 필요하다.

Kinect 소비전력은 최대 5.9W이므로 13W 어댑터는 여유가 충분하다.

### 연결 순서

1. 돼지코 → MS 어댑터 → 콘센트. **전원 LED 점등 확인**
2. 데이터 케이블을 PC의 **USB 3.0 이상** 포트에 **직결**

USB 2.0은 대역폭 부족으로 깊이 스트림이 실패한다. USB 허브 경유도 실패 원인이므로 메인보드 직결이 필요하다.

## 7. 최종 보고서용 문구

> 분석 환경은 Windows 11, AMD Ryzen 5 7500F, NVIDIA RTX 5060(32GB RAM)에서 구성하였다. Azure Kinect DK의 3D 스켈레톤 추출에는 Azure Kinect Sensor SDK v1.4.2와 Body Tracking SDK v1.1.2를 사용하였다. Body Tracking SDK는 제조사의 MSI 배포가 중단되어 NuGet 패키지에서 런타임 구성요소를 추출해 구축하였으며, 추론 실행 환경으로는 CUDA 대신 DirectML을 채택하였다. 이는 배포된 CUDA 의존성이 CUDA 10.0 기반으로 본 연구에 사용된 GPU 세대를 지원하지 않기 때문이다. 자세 추정 파이프라인은 Python 3.13.7 환경에서 pykinect-azure 0.0.4를 통해 구현하였다.
