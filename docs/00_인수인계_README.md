## 3. 이미 내린 결정과 이유 (재논의 금지)

초안(v1) 제출 후 공개 데이터를 직접 검증해 네 가지를 수정했다. **근거가 있는 결정이므로 되돌리지 말 것.**

### 3.1 Azure Kinect는 Ground Truth가 아니다 → 기준 비교 장비

Kinect도 마커 없는 추정 장비이며 자체 오차가 있다. 특히 고관절·가려진 분절이 취약(ICC 0.64 수준). 관측된 불일치는 두 장비 오차의 합이므로 스마트폰만의 오차로 해석할 수 없다. 분석 프레임을 `정확도 검증`에서 **`방법 비교(method comparison)`** 로 바꿨다.

### 3.2 CoM 기반 STS Power → Alcazar(2018) 검증식

단일 2D 45° 뷰로는 질량을 얻을 수 없고 CoM 수직변위는 원근 왜곡을 받는다. Alcazar 식은 **체중·신장·의자높이·5STS 시간** 넷만 필요하고 다리 길이 실측이 불필요하다. 60–93세 718명에 3종 장비로 검증됨.

핵심은 이것이다 — **영상이 담당하는 입력은 `시간` 하나이고, 시간은 2D 영상이 가장 정확하게 재는 지표다**(마커 기반 대비 r=0.997). 가장 약한 고리를 가장 강한 고리로 교체한 것이다.

```
F = 0.9 × 체중 × g                    (정강이·발은 상승하지 않음)
d = 0.5 × 신장 − 의자 좌면 높이
v = d / (1회 반복시간 중 신축 국면)
P = F × v ,  상대파워 = P / 체중 (W/kg)
```
문헌 참조치(약 75세): 남 2.6±0.7, 여 2.0±0.6 W/kg. 계산값이 크게 벗어나면 코드 오류 신호.
**미확인**: 신축 국면 비율과 계수는 Alcazar 2018 원문으로 최종 확인 필요.

### 3.3 근감소증 위험군 분류 → 저신체기능 선별의 증분가치

**가장 중요한 변경이다.** 공개 데이터 405명에 사지근육량·악력·보행속도·근감소증 진단이 **하나도 없다.** 직접 열 이름을 전수 확인했다. 따라서 근감소증 분류기는 원리적으로 학습 불가능하다.

대신 AWGS 2019가 인정한 **5STS ≥ 12초(저신체기능)** 를 대리지표로 쓰고, 질문을 이렇게 바꿨다.

> 초시계로는 얻을 수 없는 동작 품질 지표(체간 전방경사·각속도·좌우 비대칭)를 5STS 시간에 추가하면 예측이 개선되는가?

모델 3개 계단 비교로 순환논리를 차단한다.

| 모델 | 입력 |
|---|---|
| M0 | Age, Sex, BMI |
| M1 | M0 + 5STS 시간 |
| M2 | M1 + G3 통과 동작 품질 지표 |

**보고 지표는 절대 성능이 아니라 ΔR² / ΔAUC다.** 개선이 없어도 유효한 결과이며, 그 경우 결론은 "2D 영상의 가치는 시간 측정의 자동화·객관화에 있다"가 된다. 표기는 `근감소증 진단`이 아니라 **`저신체기능 선별`** 로 고정한다.

### 3.4 데이터 수집보다 논문 재현을 먼저

특징 추출 코드가 검증되지 않은 상태로 자체 데이터를 수집하면 코드 수정 시 전량 재분석이다. 재현은 공개 코드·데이터로 하므로 비용이 거의 없다. **이 결정은 이미 성과를 냈다** — §4 참조.

## 5. 반드시 알아야 할 함정 5개

모르면 조용히 틀린 결과가 나온다.

### 5.1 `dataClean.csv` 와 `dataClean_text.csv` 는 다른 버전

| | 행 | 열 | 5STS 평균 |
|---|---|---|---|
| `dataClean.csv` | 405 | 738 | **11.40초** ← 논문과 일치 |
| `dataClean_text.csv` | 405 | 700 | 11.13초 |

**405행 중 47행의 `time` 값이 다르다.** 서로 다른 시점의 export다. 섞어 쓰면 조용히 틀린 값이 들어간다.

**규칙**: 분석은 `dataClean.csv` 하나만 쓴다. `_text`에서는 `subjectid` 열만 가져온다.

### 5.2 `dataClean.csv` 의 subjectid 는 전부 `'0'` (익명화)

원본 8자 ID는 `dataClean_text.csv`에만 있다. 다행히 `framerate`·`Age`가 **405/405 행 단위로 일치**하므로 행 순서가 같다. 행 인덱스로 복원한다.

```python
import pandas as pd
dc   = pd.read_csv('stats/dataClean.csv')
text = pd.read_csv('stats/dataClean_text.csv')
dc['subjectid'] = text['subjectid'].values   # 행 순서 정렬 확인됨
```

`orientation` 열이 두 파일에서 0/405 일치인데, 숫자 코드 vs 문자 라벨 차이다. 파일명의 `_text`가 그 의미다. 오류 아니다.

### 5.3 `videos/np` 다운로드 불완전 — 629 / 767

최종 코호트 405명 중 **81명이 자체 실행 결과에 없다.** 원인 분해:

| 원인 | 인원 |
|---|---|
| `.npy` 파일 자체가 없음 | **81** |
| `.npy`는 있으나 처리 실패 | **0** |

**처리 실패 0건 = 파이프라인 오류 없음.** Google Drive 대용량 폴더 zip 다운로드가 조용히 잘리는 현상이다.

**Phase 4에는 영향 없다.** 증분가치 분석은 완비된 `dataClean.csv`를 그대로 쓴다. 재다운로드는 자체 파이프라인을 405명 전원에 돌려볼 때만 필요하며, 그때는 웹 zip 대신 `rclone` 권장.

### 5.4 `Height` 는 인치, `Weight` 는 파운드

`dataClean.csv`의 단위다. BMI 역산으로 확인했다(70 in / 168 lb → 24.1). cm·kg로 착각하면 Alcazar 파워가 전부 틀린다.

### 5.5 Jo et al. 2022 (Sensors) 는 sit-to-stand 를 시험하지 않았다

Azure Kinect 검증 논문으로 인용하는 문헌인데, 실제 대상은 **스쿼트·런지·리치**다. STS는 포함되지 않았다.

초기 문서 두 개(`연구프로세스_재구성_v1`, `도메인지식_입문_v1`)에 이 수치가 STS 검증인 것처럼 적혀 있다. **v2 계획서에서 정정했고, 오히려 한계 4번으로 승격했다** — STS에 대한 Kinect 일치도 자료가 희박하다는 것이 본 연구의 기여 근거가 된다.

|---|---|

| 배럴 규격 | 외경 4.5mm / 내경 3.0mm / 핀 직경 0.6mm |
| 케이블 요구 | 1.5A 이상 지원 |
| 대체 경로 | **USB-C ↔ USB-C 케이블 한 개로 전원+데이터 동시 공급 가능** |

**핵심**: 정품은 **5V USB 어댑터**다. 12V·9V 같은 일반 DC 어댑터를 배럴이 맞다고 연결하면 5.9W 장치에 과전압이 걸린다.

**안전 순서**

1. 구매한 어댑터의 출력 표기를 읽는다 → **`5V`가 아니면 연결하지 않는다**
2. USB-C ↔ USB-C 경로가 가능하면 **그쪽을 우선**한다. 전압 협상이 자동이라 가장 안전하다
3. 배럴 어댑터를 쓸 경우 극성(중심 +)도 확인한다

출처: [Azure Kinect DK hardware specifications](https://learn.microsoft.com/en-us/previous-versions/azure/kinect-dk/hardware-specification)

### 실제 수령 구성 (2026-08-05 확인 완료)

| 품목 | 상태 |
|---|---|
| Kinect 본체 | ✅ |
| 전원 어댑터 **Microsoft Model 1624** — Input 100-240V, **Output 5.2V 2.5A(13W)** | ✅ 규격 적합 |
| 전원 케이블 | ✅ |
| 데이터 케이블 (PC 연결용) | ⚠️ **2026-08-08 정정 — 실제로는 확인되지 않음.** 보유 케이블 2개(C-to-C 사제, C-to-A 편의점) 모두 동봉품이 아니며 둘 다 USB 2.0 전용이다. 정품 케이블이 박스에 있는지 재확인하고, 없으면 대여처에 문의할 것 |
| **USB 3.0 데이터 케이블** | ❌ **이것만 필요** (5Gbps 표기, A쪽 혀 파란색·핀 9개) |
| 돼지코 (미국식 납작 2핀 → 한국식 둥근 2핀) | ⬜ **불필요.** MS 1624는 USB-A 출력 5V 충전기이므로 한국 플러그 5V 2A USB-A 충전기로 대체된다 |

어댑터 입력이 **100-240V 프리볼트**라 한국 220V에 그대로 쓸 수 있다. **변압기는 필요 없고 쓰면 안 된다.** 플러그 형상 변환(돼지코)만 필요하며 다이소에서 1,000~2,000원이다.

**연결 순서**: ① 전원 먼저 연결 → LED 확인 ② USB를 **3.0 이상** 포트에 **직결**(허브 경유 금지, USB 2.0은 대역폭 부족으로 깊이 스트림 실패)

## 11. Body Tracking SDK — MSI 배포 중단 대응 (중요)

**Microsoft가 Body Tracking SDK의 MSI 배포를 중단했다.** 공식 문서의 msi 링크는 404다. Sensor SDK 저장소도 2024-08-22에 아카이브됐다.

**해결 완료.** NuGet 패키지에서 필요한 파일만 추출해 `k4abt_sdk/bin/`에 조립해 두었다(238MB). 상세는 `k4abt_sdk/README.md`.

| 항목 | 경로·방법 |
|---|---|
| Sensor SDK v1.4.2 | [GitHub 릴리스](https://github.com/microsoft/Azure-Kinect-Sensor-SDK/releases) — **MSI 정상 동작**. `k4aviewer.exe` 포함 |
| Body Tracking 1.1.2 | `k4abt_sdk/bin/` 조립본. `install_to_program_files.ps1`로 배치(관리자 권한) |
| Python 연동 | `pip install pykinect-azure` |
| G0 검증 | `python scripts/verify_kinect.py` — 샘플 뷰어가 없으므로 이걸로 대체 |

**CUDA 대신 DirectML을 쓴다.** NuGet의 CUDA 의존성은 **CUDA 10.0 / cuDNN 7**(2019년)이라 이 PC의 **RTX 5060(Blackwell)** 을 지원하지 않는다. Windows의 GPU 기본 실행 경로가 DirectML이고 `directml.dll`이 onnxruntime 패키지에 포함되어 있어, CUDA 패키지 590MB를 받지 않아도 GPU 추론이 된다. 실패 시 `--cpu` 옵션으로 전환 — 녹화 후 오프라인 처리 방식이라 속도가 문제되지 않는다.

**`k4abt_sdk/bin/`을 삭제하지 말 것.** NuGet 경로도 사라질 수 있으므로 이 폴더가 유일한 백업이다.

**미검증**: `scripts/verify_kinect.py`는 하드웨어 없이 작성했다. 실제 장비 첫 실행 시 경로·API 오류가 날 수 있다. 오류 메시지를 기록해 둘 것.
