## Part 1. 임상 도메인 — 근감소증과 의자 일어서기

### 근감소증(Sarcopenia)이란

나이가 들면서 **근육의 양이 줄고, 힘이 약해지고, 몸이 느려지는 것**이 함께 오는 상태다. 병명이지 노화의 자연스러운 결과라는 뜻이 아니다. 낙상 → 골절 → 입원 → 더 큰 근력 저하로 이어지는 악순환의 출발점이라서 조기 발견이 중요하다.

핵심은 **세 가지가 별개**라는 점이다.

| 구분 | 뜻 | 재는 방법 |
|---|---|---|
| 근육량 (mass) | 근육이 얼마나 있나 | DXA, BIA(체성분 분석기) |
| 근력 (strength) | 얼마나 센 힘을 낼 수 있나 | 악력계 |
| 신체기능 (performance) | 실제로 몸을 얼마나 잘 쓰나 | 보행속도, 의자 일어서기 |

근감소증 진단은 이 셋을 조합해서 한다. **우리 연구는 세 번째(신체기능)만 다룬다.** 이게 왜 중요한지는 Part 6의 `대리지표` 항목에서 다시 나온다.

### AWGS 2019 기준

AWGS는 Asian Working Group for Sarcopenia, 아시아 근감소증 연구그룹이다. 아시아인 체격에 맞춘 기준을 2019년에 갱신했고, 한국 임상에서 표준으로 쓴다. 유럽 기준은 EWGSOP2다.

우리가 알아야 할 숫자는 세 개뿐이다.

- **악력**: 남 28kg 미만, 여 18kg 미만 → 근력 저하
- **보행속도**: 6m 구간 1.0 m/s 미만 → 신체기능 저하
- **5회 의자 일어서기: 12초 이상 → 신체기능 저하**

`possible sarcopenia(근감소증 의심)`는 근력 저하 **또는** 신체기능 저하 중 하나만 있어도 붙는다. 확진에는 근육량 측정이 필요하다.

**세 번째 항목이 우리 연구의 열쇠다.** 초시계 하나로 재는 12초 기준이 국제 합의 문서에 들어 있다. 즉 우리가 영상에서 시간을 정확히 뽑아내기만 하면, 그 결과를 임상적으로 인정된 임계값에 바로 대조할 수 있다. DXA나 악력계 없이도 "저신체기능 의심"이라고 말할 근거가 생긴다.

### Sit-to-Stand(STS) 검사

의자에 앉았다 일어서기다. `5회 최대한 빠르게`가 표준 형태이고, `5-rep STS`, `5STS`, `5×STS`, `chair stand test`, `기립검사` 모두 같은 것을 가리킨다. (`30초 동안 몇 번`을 재는 30초 버전도 있는데, AWGS와 우리 연구는 5회 버전을 쓴다.)

이 동작 하나를 왜 그렇게 중시하나.

- 하지 근력·파워를 동시에 요구한다
- 도구가 필요 없다
- 일상 동작 그대로다 — 실험실 과제가 아니라 실제로 하루에 수십 번 하는 행동이다
- 수십 년 축적된 참조 데이터가 있다

선행 논문의 평균은 11.4±3.4초(범위 4.3–32.9초)였고, 임상 참조치(Bohannon)는 7.5±2.4초다. 우리 프로세스 문서에서 확인한 실제 분포는 이렇다.

| 연령대 | n | 평균 5STS | 12초 이상 |
|---|---|---|---|
| 18–49 | 299 | 10.8초 | 32% |
| 50–64 | 60 | 12.4초 | 50% |
| 65+ | 46 | 14.2초 | 65% |

나이가 들면 느려지는 게 데이터로 보인다. 동시에 **65세 이상이 46명뿐**이라는 것도 보인다. 이게 우리가 고령층 일반화를 주장할 수 없는 이유다.

## Part 2. 생체역학 용어

### 관절각(Joint Angle)

세 점으로 만드는 각도다. 무릎각이라면 발목–무릎–고관절 세 점을 잇는 두 벡터 사이의 각이다. 자세 추정이 관절 좌표를 주면 각도는 벡터 내적으로 계산된다. 개념적으로 어려운 게 없다.

```
cos(θ) = (v1 · v2) / (|v1| |v2|)
```

### 체간 전방경사(Trunk Lean)

일어설 때 상체를 앞으로 얼마나 숙이는지다. 선행 논문 정의는 `고관절에서 올린 수직 벡터`와 `우측 고관절 → 목 벡터` 사이의 각이다.

**왜 이 지표를 중시하나.** 다리 힘이 약한 사람은 상체를 더 많이 앞으로 던져서 관성으로 일어선다. 즉 체간 경사는 **하지 근력 부족의 보상 동작**이다. 선행 논문에서 관절염 진단과 유의하게 연관된 지표가 바로 이것이었다(R=0.18, p<0.001). 초시계로는 절대 잡을 수 없는 정보이고, 그래서 "영상이 초시계보다 나은 점"의 후보다.

### 각속도·각가속도

각도를 시간으로 미분하면 각속도, 한 번 더 미분하면 각가속도다. 이산 데이터에서는 그냥 차분이다.

```
각속도[i] = (각도[i+1] - 각도[i]) × fps
각가속도[i] = (각속도[i+1] - 각속도[i]) × fps
```

`framerate로 정규화`란 표현이 이것이다. 프레임 간격이 아니라 초 단위로 바꾸는 것뿐이다.

**주의할 점 하나가 Part 4에서 나온다. 미분은 노이즈를 증폭시킨다.** 각가속도는 두 번 미분한 값이라 가장 신뢰하기 어렵다. 우리 사전등록 기대치표에서 각가속도 ICC를 0.40–0.70으로 낮게 잡은 이유다.

### 무게중심(CoM, Center of Mass)

신체 전체의 질량이 한 점에 모여 있다고 볼 때 그 점이다. 사람이 서면 대략 배꼽 약간 아래, 골반 안쪽에 있다. 자세가 바뀌면 위치도 바뀐다.

정확히 구하려면 각 신체 분절(몸통, 허벅지, 정강이…)의 질량비와 위치를 알아야 하고, 그건 3D 좌표와 인체측정 표준값이 필요하다. **2D 영상 한 대로는 신뢰성 있게 못 구한다.** 이게 원 계획의 `CoM 기반 STS Power`를 바꾼 이유다.

### 근력(Strength)과 파워(Power)의 차이 — 이게 핵심이다

혼동하기 쉬운데 연구 전체의 논리가 여기 걸려 있다.

- **근력** = 낼 수 있는 최대 힘. 천천히 무거운 걸 밀 수 있는 능력.
- **파워** = 힘 × 속도. **빨리** 힘을 낼 수 있는 능력.

```
Power(W) = Force(N) × Velocity(m/s)
```

노화에서 **파워가 근육량이나 근력보다 더 빨리, 더 이른 나이부터 떨어진다.** 그리고 일상 동작(계단, 버스 타기, 넘어질 때 버티기)은 대부분 파워를 요구한다. 그래서 파워가 조기 신호로서 더 민감하다.

의자에서 일어서는 건 본질적으로 **몸을 위로 들어올리는 일**이다. 그래서 여기서 파워를 추정할 수 있다.

### Alcazar 식 — 왜 이걸로 바꿨나

물리적으로 아주 단순하다.

```
파워 = 일 / 시간 = (힘 × 수직이동거리) / 시간
```

각 항을 이렇게 채운다.

| 항 | 값 | 이유 |
|---|---|---|
| 힘 | 0.9 × 체중 × g | 정강이와 발은 함께 올라가지 않으므로 체중의 90%만 계산 |
| 수직이동거리 | 0.5 × 신장 − 의자 높이 | CoM이 의자 높이에서 신장의 절반 위치까지 올라간다고 근사 |
| 시간 | 5STS 시간을 반복수로 나눈 뒤 신축 국면 비율 적용 | 앉는 동작은 파워를 쓰지 않으므로 일어서는 국면만 |
| 상대파워 | 결과 ÷ 체중 (W/kg) | 체격 차이 보정 |

필요한 입력은 **체중, 신장, 의자 높이, 5STS 시간** 넷뿐이다. 다리 길이 실측도 필요 없다. 60–93세 718명을 대상으로 선형변위계·Nottingham power rig·force plate 3종에 검증되었고, 4개 후보식 중 노쇠·저악력 판별력이 가장 높았다.

**전략적으로 중요한 점**: 이 넷 중 영상이 담당하는 것은 `시간` 하나다. 그리고 시간은 2D 영상이 가장 잘 재는 지표다(선행 논문에서 마커 기반 대비 r=0.997, 거의 완벽). 나머지 셋은 줄자와 체중계로 재면 된다.

반면 CoM 기반 파워는 2D 영상이 가장 못하는 것(3D 위치와 질량)을 요구한다. 같은 목표를 정반대 방향으로 접근하는 셈이라 교체했다.

참조치(약 75세): 남 2.6±0.7 W/kg, 여 2.0±0.6 W/kg. 우리 계산값이 이 범위에서 크게 벗어나면 코드 오류 신호로 쓸 수 있다.

## Part 3. 자세 추정 기술

### 2D 자세 추정

영상 프레임에서 관절 위치를 **픽셀 좌표(x, y)** 로 찍어주는 모델이다. 출력은 `keypoint` 또는 `landmark`라 부른다.

| | keypoint 수 | 특징 |
|---|---|---|
| **OpenPose** | 25 | 선행 논문이 사용. CUDA/Caffe 빌드 필요해 설치가 까다롭다 |
| **MediaPipe Pose** | 33 | 설치 간단, 스마트폰에서도 실시간. 골반 정의가 OpenPose와 다르다 |

**두 모델의 출력은 서로 호환되지 않는다.** keypoint 개수도 정의도 다르다. 그래서 우리가 MediaPipe를 쓰면 논문의 수치와 직접 비교할 수 없고, 대신 **전처리 방식을 똑같이 맞춰서** 방법 수준의 비교 가능성을 확보한다.

### 2D의 근본 한계

카메라는 3차원을 2차원에 투영한다. 이 과정에서 잃는 정보가 있다.

- **깊이가 없다** — 카메라를 향해 움직이는 성분은 안 보인다
- **원근 왜곡** — 카메라에 가까운 쪽이 크게 찍힌다. 각도가 실제와 달라진다
- **평면 혼합** — 45° 각도는 측면(sagittal)과 정면(frontal) 정보가 섞인 값이다. 순수한 측면 무릎 굴곡각이 아니다

선행 논문이 한계로 명시한 항목이다. 우리도 같은 한계를 갖는다.

### 왜 45°인가

- **측면(0°)**: 무릎·고관절 굴곡을 잘 본다. 좌우 비대칭은 못 본다(다리가 겹친다)
- **정면(90°)**: 좌우 비대칭을 잘 본다. 굴곡 각도는 못 본다
- **45°**: 둘 다 어느 정도 본다. 대신 둘 다 부정확하다

의도적인 타협이다. 원래 목적이 "집에서 스마트폰 한 대로"였기 때문에 카메라를 두 대 놓을 수 없었다.

### Azure Kinect는 무엇이 다른가

Microsoft의 **깊이 센서(depth camera)** 다. 적외선을 쏘아 되돌아오는 시간으로 거리를 재기 때문에 3차원 좌표를 직접 얻는다. Body Tracking SDK가 32개 관절의 3D 스켈레톤을 준다.

**중요: Azure Kinect도 정답(ground truth)이 아니다.** 이것 역시 알고리즘이 추정하는 값이고, 진짜 기준은 몸에 반사 마커를 붙이고 여러 대의 카메라로 찍는 **마커 기반 모션캡처**(Vicon 등)다. 선행 논문의 실험실 검증도 8대 카메라 + 31개 마커 + 100Hz를 썼다.

Azure Kinect의 보고된 오차:

| 항목 | 값 |
|---|---|
| STS·스쿼트·균형 과제 전반 | ICC 0.83–0.95, 각도 오차 3–6° |
| 체간 기울기 | ICC 0.88, 평균절대오차 5° |
| 무릎각 (정면) | ICC 0.90–0.92 |
| **고관절각** | **ICC 0.53–0.83 (가장 약함)** |
| 가려진 부위 | 신뢰 어려움 |

그래서 우리 문서에서 `Ground Truth` 대신 `기준 비교 장비(reference standard)`로 바꿨다. 체간각 오차 5°짜리 장비를 기준으로 스마트폰 체간각을 검증하면, 결과에는 **두 장비의 오차가 합쳐져** 들어간다. 이걸 모른 채 "스마트폰이 부정확하다"고 결론내면 틀린 해석이다.

참고로 하드웨어는 2023년 10월 단종되었지만 SDK와 펌웨어는 2027년까지 유지된다. 연구실에 실물이 있으면 문제없다.

## Part 4. 신호처리

자세 추정 출력은 프레임마다 미세하게 떨린다(jitter). 관절 위치가 실제로 안 움직였는데도 픽셀 단위로 흔들린다. 이걸 그대로 미분하면 각속도가 쓰레기가 된다. 그래서 필터링이 필수다.

### 6Hz 저역통과 필터

**저역통과(low-pass)** = 낮은 주파수는 통과, 높은 주파수는 차단.

- 사람의 의자 일어서기는 초당 1회 정도의 느린 동작이다 → **낮은 주파수**
- 자세 추정 jitter는 프레임마다 바뀐다 → **높은 주파수**

주파수가 다르니 분리할 수 있다. 6Hz를 경계로 잡는 건 인체 동작 분석의 관례적 값이다. 30fps 촬영이면 Nyquist 주파수가 15Hz이므로 6Hz 차단은 안전한 범위에 있다.

**Butterworth**는 필터 종류 이름이다. 통과 대역이 평탄해서 생체역학에서 표준으로 쓴다.

**zero-lag(무위상지연)** 이 중요하다. 일반 필터는 신호를 시간축으로 조금 밀어버린다(위상 지연). 우리는 **시간을 재는 연구**라서 밀리면 안 된다. 그래서 앞으로 한 번, 뒤로 한 번 필터를 걸어 지연을 상쇄한다. Python으로는 `scipy.signal.filtfilt`다.

```python
from scipy.signal import butter, filtfilt
b, a = butter(5, 6/(fps/2), btype='low')   # 5차, 6Hz 정규화 차단주파수
filtered = filtfilt(b, a, signal)           # 양방향 = zero-lag
```

> 구현 주의: `filtfilt`는 양방향으로 걸기 때문에 실효 차수가 2배가 된다. 논문의 `fifth-order zero-lag`를 `butter(5, ...)` + `filtfilt`로 해석했는데, Phase 1에서 논문 코드와 결과를 대조하며 확인할 항목이다.

### 신장 정규화

픽셀은 물리 단위가 아니다. 같은 사람이 카메라에 가까이 서면 픽셀 좌표가 커진다. 그래서 모든 좌표를 **픽셀로 잰 신장**으로 나눈다. 그러면 카메라 거리와 체격에 무관한 무차원 값이 된다.

선행 논문은 신장을 `코–발목 거리의 95백분위수`로 정의했다. 최댓값이 아니라 95백분위수를 쓴 이유는 이상치 프레임을 배제하기 위해서다.

### 미분이 노이즈를 키운다

주파수 f 성분을 미분하면 진폭이 f배가 된다. 즉 **고주파 노이즈가 미분할 때마다 증폭된다.**

| 신호 | 미분 횟수 | 신뢰도 |
|---|---|---|
| 각도 | 0 | 가장 좋음 |
| 각속도 | 1 | 중간 |
| 각가속도 | 2 | 가장 나쁨 |

우리가 각가속도 ICC를 0.40–0.70으로 낮게 예상한 근거다. 필터링을 먼저 해야 하는 이유이기도 하다.

### 국면 분할(phase detection)

5회 동작에서 각 회의 시작·끝을 찾아야 한다. 선행 논문의 방법은 단순하다. **코의 수직 위치**를 보고 국소최소(앉은 상태)와 국소최대(선 상태)를 찾는다.

- 국소최소 → 국소최대 = STS 국면(일어서기)
- 국소최대 → 국소최소 = stand-to-sit 국면(앉기)

`local minimum`, `local maximum`이란 표현이 이것이다. 코를 쓰는 건 STS 동작에서 가장 크고 명확하게 상하로 움직이는 지점이기 때문이다.

## Part 5. 일치도 통계 — 가장 중요한 부분

여기가 이 연구 1단계의 전부다. 질문은 하나다.

> **"스마트폰으로 잰 값과 Kinect로 잰 값이 같다고 말할 수 있나?"**

직관적으로는 "상관계수를 구하면 되지 않나?" 싶은데 **틀렸다.** 이게 이 Part의 핵심이다.

### 상관과 일치는 다르다

실제로 계산해봤다. 같은 Kinect 측정값 10개에 대해 스마트폰이 세 가지 방식으로 틀린 경우다.

| 경우 | Pearson r | ICC(2,1) | 편향 | 95% LoA | RMSE |
|---|---|---|---|---|---|
| **A) 항상 5° 크게 읽음** | **1.000** | 0.877 | +5.0 | +5.0 ~ +5.0 | 5.0 |
| **B) 무작위로 ±5° 흔들림** | 0.891 | 0.898 | −0.2 | −8.6 ~ +8.2 | 4.1 |
| **C) 실제로 잘 일치함** | 0.999 | 0.999 | −0.0 | −1.0 ~ +0.9 | 0.5 |

**A를 보라. Pearson r이 1.000, 완벽한 상관이다. 그런데 모든 측정이 5°씩 틀렸다.**

Pearson 상관은 `두 값이 같이 움직이는가`만 본다. 한쪽이 항상 5° 크더라도 같이 움직이기만 하면 r=1이다. 하지만 임상에서 "당신의 체간 경사는 45°입니다"라고 말해야 한다면, 5° 오차는 그냥 오차다.

그리고 A와 B를 비교하면 더 재밌다. **B는 상관이 더 낮은데(0.891) ICC는 더 높다(0.898).** 상관계수 순위와 일치도 순위가 뒤바뀐다. 상관계수로 일치도를 판단하면 결론이 틀린다.

### ICC (Intraclass Correlation Coefficient, 급내상관계수)

**절대적 일치**를 본다. 전체 분산 중 `측정 대상 간의 진짜 차이`가 차지하는 비율이다.

```
ICC = (사람 사이의 분산) / (사람 사이의 분산 + 측정 방법 때문에 생긴 분산 + 오차)
```

분모에 **측정 방법 때문에 생긴 차이가 들어간다.** 그래서 A처럼 체계적으로 5° 밀린 경우 ICC가 떨어진다. Pearson이 못 잡는 것을 잡는다.

해석 관례(Koo & Li 2016):

| ICC | 해석 |
|---|---|
| < 0.50 | poor |
| 0.50 – 0.75 | moderate |
| 0.75 – 0.90 | good |
| > 0.90 | excellent |

`ICC(2,1)`의 숫자 표기는 이런 뜻이다. 첫 숫자 2 = 두 측정 방법을 모집단에서 뽑은 것으로 보는 모형(two-way random), 둘째 숫자 1 = 단일 측정값으로 판단(평균 아님). 방법 비교에는 이 형태를 쓴다.

**반드시 신뢰구간을 함께 보고해야 한다.** n=30에서 ICC 0.85가 나와도 95% CI가 0.6–0.95처럼 넓게 나온다. 점추정만 쓰면 과대주장이 된다.

### Bland-Altman 분석

ICC는 하나의 숫자라 "얼마나 틀렸나"를 못 알려준다. Bland-Altman이 그걸 알려준다.

그리는 방법이 단순하다.

- x축 = 두 측정의 **평균** (진짜 값의 추정치)
- y축 = 두 측정의 **차이** (스마트폰 − Kinect)

여기서 두 값을 읽는다.

- **편향(bias)** = 차이의 평균. 체계적으로 얼마나 밀렸나
- **95% 일치한계(LoA, Limits of Agreement)** = 편향 ± 1.96 × 차이의 표준편차. 개별 측정이 어디까지 벗어날 수 있나

위 표를 다시 보면 진단력이 드러난다.

- A: 편향 +5.0, LoA 폭 0 → **일관되게 5° 밀림. 보정하면 해결된다**
- B: 편향 −0.2, LoA −8.6~+8.2 → **평균은 맞는데 개별 측정이 최대 8° 틀림. 보정 불가**

같은 RMSE 수준이지만 대응이 완전히 다르다. 이걸 구분해주는 게 Bland-Altman의 가치다. **임상적으로는 LoA가 ICC보다 중요할 수도 있다.** 한 사람을 한 번 측정할 때 얼마나 믿을 수 있는지를 알려주기 때문이다.

### RMSE와 MAE

익숙한 것들이다.

- **MAE** = 평균절대오차. 해석이 직관적이다("평균 3.2° 틀림")
- **RMSE** = 제곱평균제곱근오차. 큰 오차에 더 큰 벌점. 단위가 원래 값과 같다

이 둘은 단위가 있어서 좋다. `체간각 MAE 4.1°`는 바로 이해된다. 반면 ICC는 무차원이라 크기 감각을 안 준다. 그래서 넷을 다 보고한다.

### 정리 — 왜 네 개를 다 쓰나

| 지표 | 답하는 질문 |
|---|---|
| Pearson r | 같이 움직이나? (일치도 판단에는 부족) |
| ICC | 값이 서로 바꿔 쓸 수 있을 만큼 같나? |
| Bland-Altman 편향 | 체계적으로 밀렸나? 보정 가능한가? |
| Bland-Altman LoA | 한 번 측정하면 최대 얼마나 틀릴 수 있나? |
| RMSE / MAE | 실제 단위로 얼마나 틀렸나? |

원 계획서에 `RMSE, MAE, ICC`가 이미 있었다. **Bland-Altman만 추가하면 된다.** 그리고 Pearson만으로 결론내지 않는 것이 중요하다.

## Part 6. 연구 설계 어휘

### 신뢰도(reliability)와 타당도(validity)

- **신뢰도** = 같은 걸 여러 번 재면 같은 값이 나오나 (일관성)
- **타당도** = 재려는 것을 실제로 재고 있나 (정확성)

신뢰도는 높지만 타당도가 낮을 수 있다. 5° 밀린 저울은 매번 같은 값을 주므로 신뢰도는 완벽하고, 타당도는 없다. Part 5의 A 경우가 정확히 이것이다.

우리 1단계는 **동시타당도(concurrent validity)** 를 본다. 새 방법과 기존 방법을 같은 시점에 함께 재서 비교하는 것이다. 그래서 Kinect와 스마트폰을 **동시에** 촬영한다. 따로 재면 사람의 컨디션 차이가 섞여서 무엇 때문인지 알 수 없다.

### 방법 비교 연구(method comparison)

`정확도 검증`과 `방법 비교`는 다른 프레임이다.

- 정확도 검증: 한쪽이 정답이라는 전제. "스마트폰이 얼마나 틀렸나"
- 방법 비교: 양쪽 다 오차가 있다는 전제. "두 방법이 서로 바꿔 쓸 수 있나"

Kinect 자체가 체간각 MAE 5°를 갖는 상황에서는 후자가 정직하다. 그래서 프레임을 바꿨다.

### 선별(screening)과 진단(diagnosis)

- **선별**: 위험한 사람을 넓게 골라낸다. 놓치지 않는 게 중요(민감도 우선). 틀려도 재검사로 넘긴다
- **진단**: 확정한다. 법적·임상적 책임이 따른다

**우리 시스템은 선별 도구다.** 의료기기 인증도 없고 근육량 측정도 없다. 화면에 `선별 참고용이며 진단이 아님`을 반드시 표시해야 하는 이유다. 이건 겸손 표현이 아니라 정확한 범위 진술이고, 심사에서 오히려 신뢰를 얻는다.

관련 용어:
- **민감도(sensitivity)** = 실제 환자를 환자로 맞히는 비율. 놓치지 않는 능력
- **특이도(specificity)** = 정상을 정상으로 맞히는 비율. 헛경보 안 내는 능력

선별은 민감도를 우선한다.

### 대리지표(proxy / surrogate)

재고 싶은 걸 직접 못 재서 대신 쓰는 지표다.

우리는 근감소증을 직접 판단할 수 없다(근육량 데이터가 없다). 대신 AWGS가 인정한 `5STS ≥ 12초`를 쓴다. 이건 **정당한 대리지표**다 — 국제 합의 문서에 있는 기준이기 때문이다. 임의로 만든 기준이 아니다.

단, 대리지표를 쓸 때는 **무엇의 대리인지 명시해야 한다.** `근감소증 진단`이 아니라 `저신체기능(AWGS 기준) 선별`이라고 써야 한다. 이 구분을 흐리면 그게 과잉주장이 된다.

### 순환논리(circularity)와 데이터 누출

만약 `5STS 시간`을 입력으로 넣고 `5STS ≥ 12초`를 예측하면, 정확도 100%가 나온다. 답을 입력에 넣었으니까. 이건 연구가 아니다.

원 계획의 위험이 이것이었다. 그래서 모델을 계단식으로 나눴다.

| 모델 | 입력 | 답하는 질문 |
|---|---|---|
| M0 | 나이, 성별, BMI | 기본 정보만으로 얼마나 아나 |
| M1 | M0 + 5STS 시간 | 시간을 더하면 얼마나 나아지나 |
| M2 | M1 + 운동학 지표 | **동작 품질을 더하면 또 나아지나** |

M1 → M2의 개선분이 **증분가치(incremental value)** 다. 이게 우리 연구의 진짜 질문이다. "영상이 초시계보다 나은 게 있나?"

### 사전등록(pre-registration)

분석하기 전에 기대치와 기준을 문서에 고정하는 것이다.

결과를 보고 기준을 정하면 어떤 결과든 좋게 포장할 수 있고, 그래서 아무 의미가 없어진다. 미리 "체간각 ICC는 0.5–0.8을 예상한다, 선행 논문이 r=0.58–0.70이었으므로"라고 써두면,

- 낮게 나와도 → **예측대로**
- 높게 나오면 → **개선을 입증**

양쪽 다 결과가 된다. 사후에 기준을 만들면 양쪽 다 잃는다. 학부 경진대회에서 이걸 하는 팀은 드물고, 그래서 눈에 띈다.

### 게이트(gate)

다음 단계로 넘어가기 전 통과해야 하는 조건이다. 7주짜리 일정에서 특히 중요하다.

가장 중요한 게이트는 **G1: 논문 재현**이다. 우리 특징 추출 코드가 논문 결과를 재현하지 못하는 상태로 자체 데이터를 수집하면, 나중에 코드를 고칠 때 전량 재분석해야 한다. 재현은 비용이 거의 없다(코드 실행뿐). 그래서 수집보다 먼저 한다.

### 한계 명시

논문의 `Limitations` 절이다. 학부생이 가장 많이 빠뜨리는 부분이면서, 심사에서 가장 크게 작용하는 부분이다.

한계를 숨기면 심사위원이 찾아내고, 그러면 연구자가 몰랐다는 인상을 준다. 먼저 밝히면 알고 통제했다는 인상을 준다. 같은 사실인데 평가가 반대가 된다.

## Part 7. ML 검증에서 조심할 것

AI 전공이니 대부분 알겠지만, 임상 데이터에서 특히 걸리는 것들만 짚는다.

### 피험자 수준 분할이 필수다

한 사람이 3 trial을 찍었다면, **같은 사람의 trial이 train과 test에 나뉘어 들어가면 안 된다.** 모델이 조건을 배우는 게 아니라 그 사람을 외운다. 성능이 부풀려진다.

`GroupKFold`나 `StratifiedGroupKFold`로 subject id를 group으로 넣어야 한다. 일반 `KFold`를 쓰면 누출이다.

### 클래스 불균형

`OA_check`는 405명 중 양성 30명, 7.4%다.

- 전부 "음성"이라 답하는 모델의 정확도가 **92.6%** 다. 정확도(accuracy)는 무의미하다
- **ROC-AUC도 불균형에서 낙관적으로 나온다.** 음성이 압도적으로 많으면 위음성률이 작아 보인다
- **PR-AUC**(정밀도-재현율 곡선 아래 면적)를 함께 봐야 한다. 양성 클래스에 집중한다

우리 문서에서 둘을 병기하라고 한 이유다. 그리고 30명은 어떻게 해도 작다 — 한계로 명시해야 한다.

### 소표본에서의 과적합

405명에 738개 열이다. 특징이 표본보다 많으면 우연한 패턴을 학습한다.

- G3(일치도 검증)를 통과한 지표만 입력으로 쓴다. 이게 이론 기반 특징 선택이다
- 하이퍼파라미터 탐색과 성능 추정을 분리한다(**nested CV**). 같은 데이터로 튜닝하고 평가하면 성능이 부풀려진다
- 반복 CV로 분할 운에 따른 변동을 확인한다

### 결과 해석

목표를 `AUC 0.9 달성`으로 두면 안 된다. 405명, 양성 30명에서 그런 숫자가 나오면 오히려 의심스럽다.

목표는 **ΔAUC / ΔR²** 다. "동작 품질 지표를 넣으니 R²가 0.14에서 0.19로 올랐다"가 결과다. 작아도 유효하다. 만약 개선이 없으면 그것도 결과다 — 결론은 "영상의 가치는 품질 지표보다 시간 측정의 자동화에 있다"가 되고, 이 역시 방어 가능한 주장이다.

**SHAP**은 어떤 특징이 예측에 얼마나 기여했는지 분해해서 보여준다. 의료 도메인에서는 "왜 그렇게 판단했나"를 설명해야 하므로 거의 필수다.

## 부록. 우리 문서의 어려운 문장 해독

프로세스 문서에 나온 표현을 하나씩 옮긴다.

| 원문 | 뜻 |
|---|---|
| Azure Kinect를 Ground Truth로 활용 | 잘못된 표현. Kinect도 오차가 있으니 `기준 비교 장비`로 |
| 동시타당도 검증 | 두 장비로 같은 동작을 동시에 찍어 결과를 비교 |
| ICC(2,1) + Bland-Altman | 두 측정이 서로 바꿔 쓸 수 있나 + 얼마나 어떻게 틀렸나 |
| 95% 일치한계(LoA) | 한 번 측정했을 때 오차가 들어갈 범위 |
| 6Hz 5차 zero-lag Butterworth | 자세추정 떨림 제거 필터. 시간이 밀리지 않게 양방향으로 적용 |
| 신장 정규화 (코–발목 95백분위) | 픽셀 좌표를 체격·거리 무관한 값으로 변환 |
| 국소최소/최대로 국면 분할 | 코 높이가 가장 낮은 때 = 앉음, 가장 높은 때 = 섬 |
| 이산미분, framerate 정규화 | 프레임 간 차이를 초 단위 변화율로 변환 |
| AWGS 5STS ≥12초 | 아시아 근감소증 기준의 저신체기능 임계값 |
| possible sarcopenia | 근감소증 의심. 근력 또는 기능 저하 하나만 있어도 해당 |
| Alcazar 상대 STS 파워 | 체중·신장·의자높이·시간으로 하지 파워 추정, 체중으로 나눈 W/kg |
| 증분가치(incremental value) | 기존 지표에 새 지표를 더했을 때의 개선분 |
| 대리지표 | 직접 못 재는 것을 대신하는 인정된 지표 |
| 사전등록 기대치 | 분석 전에 예상값과 기준을 고정해 사후 합리화를 막는 장치 |
| subject 수준 5-fold CV | 같은 사람의 데이터가 train/test에 갈라지지 않게 분할 |
| ROC-AUC와 PR-AUC 병기 | 불균형 데이터라 ROC만으로는 낙관적이므로 둘 다 보고 |
| nested CV | 하이퍼파라미터 탐색과 성능 추정을 분리 |
| G3 통과 지표만 모델 입력 | 믿을 수 있다고 검증된 지표만 학습에 사용 |

## 더 읽을 것

우선순위 순이다.

1. **선행 논문 본문** — [PMC9985590](https://pmc.ncbi.nlm.nih.gov/articles/PMC9985590/). Methods 절만 정독해도 Part 2~4가 정리된다. 무료 전문
2. **AWGS 2019 합의문** — [JAMDA](https://www.jamda.com/article/S1525-8610(19)30872-2/abstract). 표에 있는 기준값만 봐도 충분
3. **ICC 선택 가이드** — Koo TK, Li MY. *J Chiropr Med* 2016;15:155-63. ICC 형태를 어떻게 고르는지에 대한 표준 참고문헌
4. **Bland-Altman 원논문** — Bland JM, Altman DG. *Lancet* 1986;327:307-10. 짧고 명료하다
5. **Azure Kinect 검증** — [Sensors 2022;22:9819](https://pmc.ncbi.nlm.nih.gov/articles/PMC9785788/). 왜 Ground Truth가 아닌지의 근거
6. **Alcazar 파워 검사** — [PubMed 30179662](https://pubmed.ncbi.nlm.nih.gov/30179662/). 식의 정확한 계수 확인용 (Phase 0 확인 항목)
